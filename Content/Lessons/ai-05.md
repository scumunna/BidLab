# From predicted value to a price

Predictive bidding is the act of turning three predictions into one number you are willing to pay. The chain is the same identity that has run through this track, now read as a pricing rule:

$$ bid\ value = pCTR \times pCVR \times value\ per\ conversion $$

The model predicts the probability of a click, the probability of a conversion given that click, and you supply what a conversion is worth. Multiply them and you have the expected value of the impression, the most you could rationally pay before any shading. Every autobidding strategy is a wrapper around this product. It decides how to translate that expected value into an actual bid given your goal and your budget.

The reason to internalize this chain is leverage. You do not control pCTR or pCVR, the model owns those, but you do control the value per conversion you feed the system. If that number is wrong, every downstream bid is wrong no matter how good the model is.

:::predict
prompt: An impression has a predicted click-through rate of 0.03, a predicted conversion rate given a click of 0.08, and a conversion worth $120. What is the expected bid value of the impression?
answer: 0.288
tolerance: 0.005
unit: $
hint: Multiply the three numbers: pCTR times pCVR times value per conversion.
explain: bid value = 0.03 x 0.08 x $120 = 0.0024 x $120 = $0.288, about 29 cents. This is the expected payoff the model prices against. Autobidding takes this number and converts it into a bid that respects your target and budget, but the number itself is only as right as the value per conversion you supply.
:::

# Autobidding: a target turns into a bid

Manual bidding asks you for a price. Autobidding asks you for a goal and computes the price itself, in every auction, using the value chain above plus live signals. Two goals dominate.

Target CPA, or tCPA, says keep my average cost per conversion near a target. It fits campaigns where every conversion is worth roughly the same, a lead, a signup, an install. The system predicts conversion probability per impression and sets bids so the realized cost per conversion lands near your tCPA.

Target ROAS, or tROAS, says return at least this much value for every dollar I spend. It fits campaigns where conversions vary in worth, a basket of $40 and a basket of $400 are not the same event. Google states it plainly: Smart Bidding uses AI to predict the value of a potential conversion every time a user searches, then adjusts bids to maximize conversion value while trying to achieve an average return on ad spend equal to your target. The target becomes a divisor: the more value the system expects, the more it bids, scaled so the ratio of value to spend meets your goal.

$$ max\ bid\ per\ click = \frac{pCVR \times value\ per\ conversion}{tROAS} $$

:::quiz
question: A campaign sells products whose order values range from about $30 to about $500. Which automated strategy is the better fit, and why?
- tROAS, because conversion values vary widely and the system should bid proportionally to each conversion's expected value
- tCPA, because every conversion is worth the same and should cost the same
- A flat manual CPM, because automation cannot handle variable value
- Maximize clicks, because clicks predict value better than value does
answer: 0
hint: When conversions are worth very different amounts, which goal lets the system bid more for the valuable ones?
explain: When conversion values vary widely, tROAS is the right strategy because it lets the system bid proportionally to each conversion's expected value, paying more to win a likely $500 order than a likely $30 one. tCPA treats every conversion as equal-cost, which wastes the spread. Google's own guidance recommends tROAS once you report conversion values and have enough data.
:::

# Value-based bidding: feeding the model what a conversion is actually worth

Value-based bidding is the discipline of reporting real conversion values, not just conversion counts, so the optimizer maximizes total value rather than total events. A model told only that a conversion happened will chase cheap, low-worth conversions. A model told that this conversion was worth $400 and that one $40 will spend up to win the valuable one.

The mechanics: for each impression the system estimates the expected conversion value, pCVR times value per conversion, and under tROAS divides by your target to get the most it will bid. Concretely, if a click has an expected conversion value of $30 and your target ROAS is 5 (you want $5 of value per $1 spent), the most the system will pay per click is $30 divided by 5, or $6. Bid more and you breach your return target; bid less and you leave winnable value on the table.

The catch is garbage in, garbage out. If your reported values are wrong, stale, or unscaled, the optimizer faithfully maximizes the wrong objective. Value-based bidding moves the highest-leverage input out of the model and onto your desk: the value number itself.

:::predict
prompt: A click has an expected conversion value of $30 (pCVR times value per conversion). Your target ROAS is 5.0, meaning you want $5 of value for every $1 spent. What is the most the system should bid per click?
answer: 6
tolerance: 0.05
unit: $
hint: Divide the expected conversion value by the target ROAS.
explain: max bid per click = expected conversion value / tROAS = $30 / 5.0 = $6.00. Paying exactly $6 returns $30 of value, which is the 5-to-1 ratio your target demands. Bidding above $6 wins more impressions but drops you below a 5x return; bidding below $6 protects the ratio at the cost of volume.
:::

# How the model replaces the manual bid modifiers

The old job was a grid of manual adjustments. A trader set a plus-20% modifier for mobile, a minus-15% for a weak geo, a plus-30% for the converting hours, each one a static guess applied uniformly. Smart Bidding dissolves that grid. It evaluates device, location, time of day, browser, operating system, query context, and audience as live signals, and it sets a bid for each individual auction rather than a few times a day.

The difference is not just automation, it is resolution. A manual mobile modifier treats every mobile impression the same. The model recognizes meaningful interactions between billions of combinations of signals, a specific device on a specific network at a specific hour for a specific audience, and prices each one separately. The single learned function subsumes the entire manual modifier table and then goes far beyond what any hand-set grid could express.

That is also why layering old manual modifiers on top of Smart Bidding usually hurts: you are overriding a per-auction model with a coarse static guess it already accounted for.

- The manual modifiers override and distort the model's per-auction bids, usually hurting performance
- The manual modifiers make the model strictly more accurate

explain: Smart Bidding already evaluates device and location, plus many more signals, for each individual auction. A static manual modifier layered on top forces a coarse, uniform adjustment onto bids the model already tuned per context, usually distorting them and hurting performance. The per-auction model subsumes the manual grid, so the grid becomes interference, not help.

# Exploration versus exploitation: the model must bid to learn

A bidder that only exploits, always pricing from what it already knows, never discovers the impressions it has not tried. So autobidders deliberately explore: they bid above and below the target for a stretch to learn the auction landscape before settling. This is the learning period, typically one to two weeks of volatile performance by design, during which the system is buying information, not just outcomes.

Google made this explicit at Google Marketing Live 2025 with Smart Bidding Exploration, described as its biggest update to bidding in over a decade. It pursues less obvious, potentially high-performing searches the campaign has not entered before, predicting conversion likelihood for queries with no history. The cost of that exploration is a temporary, chosen relaxation of your target: you lower tROAS on a sliding scale, commonly in the range of 10 to 30 percent, to let the system deprioritize short-term efficiency in favor of finding incremental volume.

The tradeoff is the core idea. Pure exploitation locks you into the impressions you already know and starves you of growth. Too much exploration burns budget probing dead ends. The right setting buys just enough information to keep improving without overpaying for it.

:::predict
prompt: You run Smart Bidding Exploration with a base target ROAS of 6.0 and choose a 20% reduction to fund exploration. What is the effective exploration target ROAS?
answer: 4.8
tolerance: 0.05
unit:
hint: A 20% reduction leaves 80% of the base target. Multiply 6.0 by 0.80.
explain: A 20% reduction leaves 100% minus 20%, or 80%, of the base target. 6.0 x 0.80 = 4.8. Lowering the effective target from 6.0 to 4.8 lets the system bid on less proven queries it would otherwise skip, paying for exploration with a temporary, bounded efficiency cut you chose on the slider.
:::

# When calibration drives an overbid

Everything above assumes the predictions are calibrated. They are not always. A miscalibrated optimizer inflates expected value, and because the bid is built from expected value, the inflation flows straight into the price. If the predicted conversion value runs 20% high, the value-based bid runs 20% high on every impression, even when the target ROAS math is applied correctly. The strategy is sound; the input is poisoned.

This is the same failure from the foundations module, now seen at the moment it costs money. A calibration ratio of 1.20, predicted over actual, does not announce itself in the ROAS report until the realized return drifts below target and the spend overshoots. The defense is to watch calibration alongside delivery: if bids are climbing and realized ROAS is sliding, suspect an inflated prediction before you blame the auction.

:::predict
prompt: The correct value-based bid for a click is $6.00, but the predicted conversion value is miscalibrated high by a calibration ratio of 1.20. What bid does the miscalibrated model produce?
answer: 7.2
tolerance: 0.05
unit: $
hint: Multiply the correct bid by the calibration ratio of 1.20.
explain: Because the bid is proportional to predicted value, a 1.20 calibration ratio scales the bid by the same factor: $6.00 x 1.20 = $7.20. The model overbids by $1.20 per click, a 20% overpayment, while the tROAS formula was applied perfectly. The fault is the inflated prediction, not the bidding logic, which is why calibration is the input an auditor checks first.
:::

:::callout warning
Predictive bidding is only as honest as two inputs you can actually audit: the value per conversion you report and the calibration of the predictions. A correct tROAS or tCPA strategy on top of an inflated prediction still overbids, dollar for dollar, in proportion to the miscalibration. Before trusting an autobidder, confirm your reported values are real and current, confirm the calibration ratio sits near 1.0, and read a sliding rise in bids against a falling realized return as the signature of an inflated prediction.
:::
