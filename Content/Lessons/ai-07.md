# What an LLM actually does in adtech

A large language model is a text and reasoning engine, not a media buyer. In the adtech workday it does four things well, all of which are drafting tasks: it sets up campaign shells from a brief, runs first-pass QA on trafficking sheets, turns a pile of metrics into a readable report, and converts a messy client request into a structured audience brief. In each case the model produces a draft fast, and a human edits and approves.

Notice the shape. The LLM is strongest when the task is "take this input and produce a structured first draft," and weakest when the task is "decide what is true" or "commit real money." A draft is cheap to check and cheap to fix. A decision is not. That single distinction predicts almost everything about where these tools help and where they hurt.

This is also why the LLM rarely replaces a role. It compresses the time between blank page and reviewable draft, which moves the human's job from producing to verifying. The skill that gains value is fast, skeptical review.

# Sizing the productivity gain

The reason teams adopt LLMs is time. The honest way to size it is per task, then aggregate. If a task takes $t_{manual}$ minutes by hand and $t_{assisted}$ minutes with the model plus review, the time saved per task is the difference, and the percent reduction is that difference over the manual time.

$$ reduction = \frac{t_{manual} - t_{assisted}}{t_{manual}} $$

Reported gains in marketing and advertising are real but vary widely. One commonly cited figure is that a third of daily generative AI users report saving at least four hours per work week, as reported in 2025 productivity surveys, and individual agency cases describe cutting campaign material production from weeks to a fraction of that. Treat any single headline number as context, not a promise, and measure your own tasks.

The trap is forgetting the review time. The assisted number must include verification, because an unverified LLM draft is not done, it is a liability waiting to ship. A gain that looks like 90% on the draft can shrink to 60% once honest review is added back in.

:::predict
prompt: Building a campaign shell from a brief takes 60 minutes by hand. With an LLM draft plus human review it takes 15 minutes total. What is the percent reduction in time for this task?
answer: 75
tolerance: 1
unit: %
hint: Subtract the assisted time from the manual time, then divide by the manual time.
explain: reduction = (60 - 15) / 60 = 45 / 60 = 0.75, or 75%. The 15-minute assisted figure must already include the human review step, because an unverified draft is not finished work. If review took longer, the reduction would shrink.
:::

# Agentic workflows and tool use

The next step beyond drafting is the agent. An agentic workflow gives the LLM tools it can call, an API to pull a report, a function to push a line item, a query to a planning system, and lets it chain those calls toward a goal instead of just producing text. The model decides which tool to use, reads the result, and decides the next step.

The industry is standardizing this layer fast. The Ad Context Protocol (AdCP), launched in late 2025 by a coalition of companies and built on the Model Context Protocol, defines core agent tasks of discovery, comparison, and campaign activation, and runs asynchronously so a human can approve while agents negotiate. In parallel, IAB Tech Lab released its Agentic RTB Framework (ARTF) v1.0 for public comment on November 13, 2025, designed to standardize agent interoperability and reportedly cut bid request and response time by up to 80%, with the comment period running to January 15, 2026.

The power and the danger are the same fact: an agent acts, it does not just suggest. A drafting LLM that hallucinates wastes a minute of your review time. An agent that hallucinates and then calls the "launch campaign" tool spends real money on a wrong decision. So the guardrail moves from "review the draft" to "gate the action."

# Hallucination and the human-in-the-loop gate

LLMs hallucinate by design, not by accident. OpenAI's September 2025 paper "Why Language Models Hallucinate" argues that training and evaluation reward confident guessing over admitting uncertainty, so models learn to bluff a plausible answer rather than say "I do not know." In adtech that shows up as an invented audience segment that sounds real, a made-up benchmark, a misread metric stated with total confidence, or an agent taking a step it cannot actually justify.

You do not fix this by trusting harder. You fix it with a gate. The human-in-the-loop is not a courtesy review, it is the control that catches the model's confident errors before they cost something. The math of the gate is simple and worth internalizing: if the model is wrong some fraction of the time and your review catches some fraction of those errors, the errors that escape to production are the product of the two miss rates.

$$ escaped = (1 - accuracy) \times (1 - catch\ rate) $$

This is why review quality matters as much as model quality. A more accurate model and a sharper reviewer both shrink the escaped error rate, but they multiply, so weakness in either one dominates. A great model with lazy review still leaks errors, and a sharp reviewer cannot fully save a model that is wrong half the time.

:::predict
prompt: An LLM drafts audience briefs that are correct 90% of the time. A human reviewer catches 80% of the errors that do occur. What fraction of all briefs ship with an uncaught error?
answer: 2
tolerance: 0.2
unit: %
hint: Errors occur on 10% of briefs, and 20% of those errors slip past review. Multiply the two.
explain: Errors occur on 1 - 0.90 = 10% of briefs. The reviewer misses 1 - 0.80 = 20% of those. Escaped error rate = 0.10 x 0.20 = 0.02, or 2%. The accuracy gap and the review miss rate multiply, so improving either one helps, but a weak reviewer or a weak model alone can dominate the result.
:::

# Where LLMs help versus where they fail

Map the work onto one axis: how expensive is a wrong answer, and how easily can a human check it. LLMs help most where errors are cheap and checkable, drafting briefs, summarizing reports, first-pass QA, rewriting copy, explaining a metric. They fail most where errors are expensive or hard to verify, committing spend, stating a number as ground truth, making a final targeting decision, or anything where a confident wrong answer ships before a human can catch it.

The practical rule that falls out: let the LLM draft, let the human decide, and put a hard gate on any agent action that spends money or changes live delivery. The productivity gain is real, but it comes from compressing the drafting time, not from removing the human from the decisions where being confidently wrong is costly.

That is the whole posture for 2026. Use the model to get to a reviewable draft faster, keep a skeptical human on the gate, and reserve full autonomy for the steps where a wrong answer is cheap to undo.

:::quiz
